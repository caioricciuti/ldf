# ldf-mcp clickhouse, end to end (2026-10-21)

`eval/bench_mcp.py --mode clickhouse`: nine tool calls an agent would make
against a ClickHouse database (discovery, then reads), each through
`ldf-mcp clickhouse` twice, once as the server ships (LDF when shorter) and
once with `--passthrough` (JSON). No model was called. `mcp.md` is the
script's own report, `mcp.json` its raw output; `texts/` keeps both texts
for the five smaller results (the four largest are regenerated by the
command below).

Machine: Apple M2 Pro, 10 cores, 16 GB, macOS 27.0.1. ClickHouse 25.8.33.6
in Docker (OrbStack) on 127.0.0.1:8124, user `ldf`, the five medium
fixtures loaded as in `site/src/content/docs/docs/mcp.md`. Repository at
f839302 plus the `--user` flag this run added to `bench_mcp.py`.

Reproduce:

```bash
cargo build --release && python3 -I eval/bench_mcp.py --mode clickhouse --url http://127.0.0.1:8124 --user ldf --out results/mcp-clickhouse
```

## What it shows

| query | rows | JSON bytes | LDF bytes | bytes ratio | o200k LDF / JSON |
|---|---:|---:|---:|---:|---:|
| users_50 | 50 | 6 909 | 3 134 | 0.45 | 0.62 |
| orders_100 | 100 | 29 465 | 13 676 | 0.46 | 0.56 |
| logs_errors_500 | 500 | 72 615 | 34 687 | 0.48 | 0.65 |
| wide_1000 | 1 000 | 540 065 | 274 626 | 0.51 | 0.43 |
| events_200 | 200 | 51 435 | 39 107 | 0.76 | 0.81 |

- `orders_100` is nested (customer object, `items` array): LDF writes it as
  a parent table and a `@records.items` child table at 0.56 of JSON's
  o200k tokens; TOON falls back to list form and is 1.07.
- `list_tables` and `users_by_country` are under the 1 024-byte default
  `--min-bytes`, so the server passes them through as JSON. The o200k
  ratios in `mcp.md` for those two are what LDF would have cost.
- `logs_10000` hit the 10 000-row cap; the LDF text carries the note block.
- Encoding costs 0.7 to 1.7 ms per call up to 500 rows, 3.8 ms at 1 000
  wide rows and 6.9 ms at 10 000 rows (p50, client side).
- The selector table in `mcp.md` is the evidence policy applied to these
  results, not something measured here. It gives JSON on `orders_100` to
  every model (`total` holds both integers and floats, so it is a `j`
  column, and no graded evaluation covers child tables with JSON cells;
  `wide_1000` has the same `json_cells` trait) and on the flat results
  above 200 rows to Opus (the 1 000-row evidence withdrew it on flat data). Without `--model`
  the server sends LDF whenever it is shorter, which is the `ldf` column.
